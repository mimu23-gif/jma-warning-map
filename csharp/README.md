# 警報発令エリア 可視化（C# / Windows標準機能のみ）

このリポジトリの**本体**です。**Windowsに最初から入っているものだけ**で動き、
ローカルにHTTPサーバを立てて既定ブラウザに地図を表示します。

元はGoogle Apps Scriptで作ったもので、同じ画面とロジックのGAS版を [`gas/`](../gas/) に残してあります
（→ [GAS版との対応](#gas版との対応)）。

- **インストール不要** — 単一の `JmaMap.exe`（43KB）と設定ファイルだけ
- **管理者権限不要** — `localhost` に固定バインドするのでURL ACL登録もファイアウォール許可も要らない
- **メモ帳だけで作れる** — ソースは全てプレーンテキスト。`.csproj` も `.ico` も `.resx` も使わない
- **追加ランタイム不要** — .NET Framework 4.8（Windows 10/11 同梱）のみ。NuGetパッケージゼロ

## 必要なもの

| 項目 | 備考 |
|---|---|
| Windows 10 / 11 | .NET Framework 4.8 が同梱されている世代 |
| `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` | Windows同梱のC#コンパイラ。ビルドに使う |
| ブラウザ | 既定ブラウザ（Edge/Chrome/Firefox いずれも可） |
| インターネット接続 | 気象庁の警報フィードと地図タイルの取得に必要 |

Visual Studio、.NET SDK、NuGet、MSBuild、Node.js は **いずれも不要** です。

## ビルド

`build.bat` をダブルクリックするだけです。

```
Compiler: C:\WINDOWS\Microsoft.NET\Framework64\v4.0.30319\csc.exe
Building JmaMap.exe ...

BUILD OK -> ...\csharp\JmaMap.exe
```

## 実行

`JmaMap.exe` をダブルクリックすると、サーバが起動して既定ブラウザに地図が開きます。
常駐中はタスクトレイにアイコンが出るので、右クリックから操作してください。

| メニュー | 動作 |
|---|---|
| ブラウザで開く | 地図をもう一度開く（アイコンのダブルクリックでも可） |
| 索引を再構築 | 境界GeoJSONを差し替えたときに実行 |
| ログを開く | `jmamap.log` を開く |
| 終了 | サーバを止めて常駐解除 |

### コマンドライン引数

| 引数 | 用途 |
|---|---|
| `--noopen` | サーバだけ起動してブラウザを開かない |
| `--selftest` | GUIを出さずに索引構築・警報取得・応答生成を一通り試し、`selftest.txt` に結果を書く |
| `--console` | 呼び出し元のコンソールにログを出す（`--selftest` と併用すると便利） |

### ズーム連動の詳細度（LOD）

同梱データは許容誤差 0.0002度（約22m）で作ってあり、**サーバがズームに応じてさらに間引いてから送ります**。
遠景では粗い形状で軽く、近景では同梱データそのままの精度になります。間引いた結果はメモリに
キャッシュするので、同じ段の2回目以降は再計算しません。

| ズーム | 許容誤差 | 実測の応答 | 頂点 | 想定する見え方 |
|---|---|---|---|---|
| 〜5 | 0.02（約2.2km） | **1.04 MB** | 16,855 | 全国表示 |
| 6〜7 | 0.008（約890m） | 2.03 MB | 38,802 | 地方表示 |
| 8〜9 | 0.003（約330m） | 4.74 MB | 99,275 | 県表示 |
| 10〜11 | 0.001（約110m） | 12.78 MB | 278,211 | 市郡表示 |
| 12〜13 | 0.0005（約56m） | 23.18 MB | 509,451 | 市街表示 |
| 14〜 | 0（同梱データそのまま・約22m） | 47.84 MB | 1,056,423 | 最大ズーム |

（全国1,309地域に警報が出ている状態での実測。いずれも未解決0件）

画面側は起動時に `/api/status` からこの表を受け取り、ズームが別の段に入ったときだけ
取り直します（400msのデバウンス付き、表示位置は動かしません）。

### ビューポート絞り込み

近景では画面内に数エリアしか入らないため、**表示範囲に重ならないフィーチャは送りません**。
クライアントは `bbox`（西,南,東,北）を付けて要求し、サーバはフィーチャごとの外接矩形と突き合わせます。

| ズーム14・全国1,840地域発表中 | 応答 | フィーチャ |
|---|---|---|
| 絞り込みなし | 63,505 KB | 1,840 |
| 東京付近のみ（0.4度×0.3度） | **793 KB** | 58 |

**80分の1**になります。外接矩形は geometry の中の数値を2つずつ組にして走査するだけで求まり
（geometry に座標以外の数値は無い）、ファイル内の位置をキーにキャッシュします。

遠景（ズーム8未満）では絞り込みません。全国が画面に入るうえ、少し動かすたびに取り直しになるためです。
絞り込みが効いている間は、地図を動かすと500msのデバウンス後に取り直します。

### 自動更新

警報は数分単位で変わるため、**60秒ごとに表示中のレイヤーを取り直します**（右パネルの「自動更新」で切替）。

- 取得が重ならないよう、前の取得が終わるまで次を出しません
- ブラウザが裏に回っている間（`document.hidden`）は取りに行きません
- 最終取得からの経過を秒単位で表示し、2.5分以上滞ると色が変わります
- 自動更新・ズーム追従では取得中の表示を出しません（毎分ちらつくため）

### 発表中の種別だけをフィルタに出す

`/api/warnings` は、**絞り込みをかける前の全国の警報**から「いま発表されている現象コードとレベル」を
集めて `available` として返します。画面はこれを見て、発表されていない種別のチップを隠します。

```json
"available": { "levels": ["chuui","keihou"], "codes": ["05","07","10","14","15","16","19","20","21","29"] }
```

- 発表中の10現象に対して、現象チップ18種のうち8種だけを表示（残り10種は非表示）
- 特別警報・危険警報が出ていなければ、レベル選択もその2つが消えます
- 隠れた種別は「他 n 種別（発表なし）も表示」を押せば出せます
- 発表が始まった種別は次回取得時に自動で表示・選択に戻ります（隠れたまま埋もれないように）
- 「リセット」で全種別の表示に戻ります

クライアント側の絞り込みだけで判定すると「自分が外した種別」と「そもそも発表がない種別」を
区別できないため、サーバが絞り込み前の集合を返す形にしています。

### 災害情報レイヤー（地震・台風）

警報とは別のレイヤーとして、いま発生している地震と台風を重ねられます。右パネルの
「災害情報レイヤー」でそれぞれオン／オフします（既定はオフ。警報の表示には影響しません）。

**地震・震度** — `bosai/quake/data/list.json` から直近24時間の地震を取り、
市区町村別の震度を**警報と同じ境界データのポリゴン**に塗ります。震源は `cod`（ISO6709の短縮形
`+32.7+130.7-10000/`）を解いて「✕」で示します。

- 震度のコードは市区町村コード（7桁）で来るため、警報と同じ解決規則
  （7桁一致 → 6桁 → 政令市の親コードへフォールバック）がそのまま使えます
- 政令市の区が親ポリゴンへ寄って図形が重なる場合は、**強いほうの震度だけを残します**
- 同じ地震の続報は最新の1件へまとめます（`eid` が鍵）
- パネルの一覧から過去の地震を選び直せます。ズーム連動のLODも警報と同じように効きます

**台風** — `bosai/typhoon/data/targetTc.json` で対象を取り、TCごとに
`forecast.json`（座標）と `specifications.json`（諸元）を読んで次を描きます。

| 要素 | 見た目 | 出どころ |
|---|---|---|
| 実績経路 | 白の実線（熱帯低気圧だった期間は薄い破線） | `track.typhoon` / `track.preTyphoon` |
| 現在位置 | 🌀 マーカー。気圧・最大風速・進行方向をポップアップ | `center` + specifications |
| 暴風警戒域 | 赤の塗り円 | `galeWarningArea`（中心と半径m） |
| 予報円 | 黄の破線円、中心を結ぶ破線 | `probabilityCircle`（半径m） |

半径はメートルで来るので Leaflet の `L.circle` にそのまま渡せます。台風データは10分、
地震の一覧は60秒キャッシュします。

**噴火警報・降灰予報** — `bosai/volcano/data/warning.json`（噴火警報）と、防災情報XMLの
`eqvol.xml` → 降灰予報の個別電文（VFVO53）から取ります。どちらも**対象が市町村コード**で来るため、
警報・震度と同じポリゴンに塗れます。

- 噴火警報は「噴火警報（居住地域）」＞「火口周辺警報」＞「噴火警報（周辺海域）」で色を分けます
- 降灰予報は「降灰」と「小さな噴石の落下」を別に塗り、火山の位置に▲を置きます
- 火山の座標は度分表記（`+3026.60+13013.03+657/` ＝ 北緯30度26.60分）で、地震の `cod`（十進度）と
  형式が違うため、緯度が90を超えていたら度分とみなして換算しています

**指定河川洪水予報** — 防災情報XMLの `extra.xml` → 個別電文（VXKO76）。河川ごとに最新1件へまとめ、
解除済みの河川は一覧に残して地図には塗りません。

> **この情報だけは河川の形で描けません。** 電文が持つコードは河川区間コード（`8303040049`）・
> 水位観測所コード・府県予報区コード（`130000`）の3つだけで、**市町村コードは含まれません**。
> 気象庁は河川の線形（洪水予報区間）のGISデータを配布していないため、地図に結合できるのは
> 府県予報区だけです。そのため塗りは府県単位（破線）にし、「右岸：〜から〜まで」の区間説明を
> 一覧のツールチップに出しています。

**津波警報・注意報** — `bosai/tsunami/data/list.json` と個別報のJSON。区域は**3桁の津波予報区コード**
（`712` 有明・八代海など）で、6/7桁前提の索引には載りません。専用の海岸線データ
（[`../data/boundaries/tsunami/`](../data/boundaries/tsunami/)・66区・24.7MB）を単独ファイルとして持ち、
コードを原文のまま突き合わせます。気象庁GISの津波予報区は**ポリゴンではなく線（PolyLine）**で
配布されているため、面ではなく海岸線として描きます。

## GeoTool.exe（境界データ変換ツール）

気象庁の予報区等GIS（シェープファイル）から、このアプリが使う都道府県別GeoJSONを作るCLIです。
`tools/build_geojson_folders.py`（geopandas必須）と同じ成果物を、**Python無しで**作れます。

ポリゴン（予報区）と折れ線（津波予報区の海岸線）の両方を読めます。図形型は自動判別し、
線は `LineString` / `MultiLineString` として書き出します。

```
GeoTool.exe convert     --in <ZIP|SHP> --out <出力フォルダ> [--suffix area] [--encoding cp932] [--layer 名前の一部]
GeoTool.exe shp2geojson --in <ZIP|SHP> --out <全国版.geojson>
GeoTool.exe split       --in <全国版.geojson> --out <出力フォルダ> [--suffix area]
GeoTool.exe merge       --in <都道府県別フォルダ> --out <全国版.geojson>
GeoTool.exe simplify    --in <フォルダ|ファイル> --out <同> --tolerance 0.0002
```

### 同梱データの作り方（2段構え）

原データは4区分で 1.88GB・4,502万頂点あり、そのまま配信するとブラウザが持ちません。
**変換 → 簡略化** の2段で作ります。

```
:: 1) 気象庁ZIP -> 高精度な都道府県別GeoJSON（1.88GB）
GeoTool.exe convert  --in ..\_work\gis_src\20230517_AreaForecastLocalM_matome_GIS.zip ^
                     --out ..\_work\boundaries_full\sikutyousonnwomatometatiikitou

:: 2) 表示用に間引く（4区分あわせて127MB）
GeoTool.exe simplify --in ..\_work\boundaries_full\sikutyousonnwomatometatiikitou ^
                     --out ..\data\boundaries\sikutyousonnwomatometatiikitou ^
                     --tolerance 0.0002
```

`--tolerance` は度で指定します（緯度1度 ≒ 111km なので 0.0002度 ≒ 22m）。同梱データはこの値です。
近景の精度をサーバ側の[ズーム連動LOD](#ズーム連動の詳細度lod)で落とす構成にしたため、
同梱データ自体は高精度なものを持たせています。

| 許容誤差 | 削減率 | 全4区分の合計 | 用途 |
|---|---|---|---|
| 0.0001（約11m） | 約85% | 約150 MB | ズーム18でも輪郭が保たれる |
| **0.0002（約22m）** | **約93%** | **127 MB** | **同梱データ。LODの元データとして使う** |
| 0.001（約111m） | 約98% | 約30 MB | 中間 |
| 0.0023（約256m） | 99.3% | 14.4 MB | 全国表示〜市町村表示向け（LOD導入前の同梱値） |
| 0.005（約557m） | 99.6% | 約8 MB | 全国表示専用 |

簡略化の副作用: 境界線が許容誤差ぶんずれるほか、**3頂点未満に潰れたリング（小島・岩礁）は削除されます**
（許容誤差0.0023度のとき、北海道の一次細分区域でポリゴン 9,435 → 157。同梱の0.0002度では
削除されるリングはこれより少なくなります）。離島のPOIが警報エリア判定から外れる可能性があります。
各ポリゴンを独立に簡略化するため、隣接区域の境界に隙間が生じることもあります。

例（配布ZIPをそのまま渡せます。展開不要）:

```
GeoTool.exe convert --in ..\_work\gis_src\20230517_AreaForecastLocalM_matome_GIS.zip ^
                    --out ..\data\boundaries\sikutyousonnwomatometatiikitou
```

### 実装上の要点

- **座標変換をしない**のが成立の鍵です。気象庁の予報区等GISはJGD2011の*地理座標*（経緯度）で配布され、
  JGD2011とWGS84の差はセンチメートル級なので、EPSG:4326としてそのまま出力できます
  （Python版の `to_crs(4326)` も実質無変換）。投影座標系（PROJCS）の入力は `.prj` を見て拒否します
- シェープファイルはリングを平坦に並べるだけなので、**外周と穴は符号付き面積で判別**します
  （ESRI仕様：外周=時計回り、穴=反時計回り）
- 座標は「doubleの厳密な10進展開を小数15桁へ正しく丸めた表記」で書きます。
  .NET Frameworkの `ToString("F15")` は有効数字15桁で頭打ちになり精度が落ちるため、
  `BigInteger` で厳密に計算しています
- ZIP内のエントリ名は日本語かつ古いものはCP932のまま（UTF-8フラグ無し）なので、
  **名前を見ずに拡張子だけで取り出します**
- DBFの文字コードは `.cpg` →（無ければ）レコード領域のUTF-8妥当性→CP932 の順で判定します

### 検証結果

| 検証 | 結果 |
|---|---|
| `split` の往復（既存188ファイル→全国版→再分割） | **188/188 が SHA256 まで完全一致** |
| 折れ線対応を入れた後のポリゴン回帰（1saibun 47ファイルの merge→split 往復） | **47/47 が SHA256 一致（回帰なし）** |
| `shp2geojson` vs geopandas（同一シェープファイル） | 属性・ジオメトリ型・座標構造すべて一致、**座標2,113,096点が誤差0.0** |
| 気象庁の実配布ZIP4本からの `convert` | 全て変換成功（Python版は府県予報区ZIPの読み込みに失敗する） |

同一ZIPからPython版と比較すると、次の点で**C#版のほうが忠実**です。

- **属性の文字コード**: 1saibun のDBFは実際にはUTF-8（言語ドライバID=0x00・`.cpg`無し）。
  GDALはCP932と誤認して `津軽` を `豢･霆ｽ` にしてしまうが、本ツールは正しく読む
- **座標**: GDALは短い表記に丸める際に数ULPずれることがある（例: 真値が `140.45000000000005` でも
  `140.45` と書く）。本ツールは読み取ったdoubleを厳密に書き出す
- **ZIPの互換性**: GDALの `/vsizip` はCP932エントリ名のZIPを開けないことがあるが、本ツールは影響を受けない

| GET | `/api/tsunami` | 津波警報・注意報（海岸線） |

`/api/quake/intensity` 以外の災害系は GET で、`?zoom=` と `&bbox=西,南,東,北` を受け付けます。

### 細分された市区町村へのフォールバック（C#版のみ）

同梱の「市町村等」は**気象警報用**の区分で、八代市が「八代市西部(4320211)／東部(4320212)」のように
割れている区域が1,805件中89件あります。一方、**震度・噴火警報・降灰予報は市全体のコード(4320200)**で
届くため、7桁一致も6桁一致も外れます。

そこで、末尾が `00` のコードが解決できなかったときだけ、**先頭5桁が同じ細分区域を全部拾って**
市全体を塗ります（[GeoIndex.FindSubdivisions](src/GeoIndex.cs)）。空振りは滅多に起きないため、
その時だけの線形走査で足ります。

> 気象庁は地震用に別途「市町村等（地震津波関係）」（146MB）を配布しており、本来はそちらが正解です。
> 同梱データを146MB増やす代わりに、上記のフォールバックで対応しています。

## メモ帳だけで編集するときの注意

1. **C# 5 の構文で書く** — Windows同梱の `csc.exe` はRoslyn以前のもので、`$"..."`（文字列補間）、
   `?.`、`nameof`、式形式メンバー、タプルは使えません（`async`/`await`・LINQ・`var` は使えます）
2. **保存はUTF-8** — Windows 11のメモ帳の既定。BOMの有無どちらでも日本語リテラルは正しく通ります
3. **`build.bat` を保存するときは「ファイルの種類: すべてのファイル」を選ぶ** — 既定のままだと
   `build.bat.txt` になってしまいます
4. **`build.bat` のコメントはASCIIで書く** — cmd.exe のコードページはCP932のため、日本語コメントは化けます
5. **バイナリを増やさない** — トレイアイコンは `SystemIcons` を借りているので `.ico` は不要です
